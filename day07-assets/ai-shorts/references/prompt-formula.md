# 씬 프롬프트 공식

## 왜 결과가 허접해 보이는가

장면을 "무엇"으로만 적으면 모델은 스톡 영상 같은 평범한 그림을 낸다.
**진짜처럼 보이게 하는 건 광원과 재질이다.** 그리고 "시네마틱", "고퀄리티",
"아름다운" 같은 말은 정보가 없어서 아무 효과가 없다.

## 프롬프트 문법 — 일곱 칸

순서대로 쓴다. 앞은 내용, 뒤로 갈수록 촬영 스펙이다.

```
① 샷 크기 + 피사체     익스트림 클로즈업 / 미디엄 / 와이드, 카메라 높이
② 재질과 상태          표면, 마모, 습기, 먼지, 스케일 단서
③ 광원                 방향 · 성질(하드/소프트) · 시각 · 색온도
④ 카메라 움직임        종류 + 속도 + 무엇을 축으로
⑤ 색                   구체적 색 이름 + 대비 + 어디가 날아가고 어디가 뭉개지는지
⑥ 광학                 초점거리 · 심도 · 플레어 · 모션블러
⑦ 세로 9:16 구도. 사람과 얼굴은 나오지 않는다. 화면에 글자·간판·라벨이 없는 장면.
```

### ② 재질이 절반이다

`콘크리트 벽` 은 렌더처럼 나온다.
`거친 노출 콘크리트, 표면에 물때가 흘러내린 자국과 미세한 기포 구멍, 모서리는
닳아 둥글다` 는 사진처럼 나온다.

무엇으로 만들어졌고, 얼마나 오래됐고, 어떻게 더러워졌는지를 적는다.

### ③ 광원이 나머지 절반이다

빛을 안 적으면 모델이 밋밋한 정면광을 쓴다. 최소한 이 셋은 적는다.

- **방향** — 역광 / 측광 / 정면 45도 / 위에서
- **성질** — 하드(그림자 경계 뚜렷) / 소프트(흐린 날, 확산)
- **시각** — 정오 / 해 뜨고 한 시간 / 해 지기 직전

### ④ 카메라는 축을 정해준다

`빠르게 움직인다` 는 아무 말도 아니다.
`피사체를 축으로 시계방향 오빗, 초당 15도` / `벽면을 따라 수직 크레인 상승,
초당 3미터, 등속` 처럼 **무엇을 기준으로 얼마나 빠르게**를 적는다.

### 쓰지 말 것

아름다운 · 멋진 · 시네마틱 · 영화 같은 · 고퀄리티 · 4K · 8K · 마스터피스 ·
최고의 · 놀라운. 전부 정보가 없다. 그 자리에 ②③④를 채운다.

## 쌍둥이 컷 — 조건 하나만 바꾸기

C3·C4처럼 **같은 구도에서 조건 하나만 바꿔 대비를 보여주는 컷**이 이 구조의
핵심이다. 그런데 Flow는 컷마다 따로 생성하므로 앞 컷을 기억하지 못한다.
"앞과 동일하게"라고만 쓰면 딴 그림이 나온다.

그래서 **두 프롬프트에 같은 문장을 그대로 복사해 넣는다.**

- 샷 크기·카메라 높이·화각 — 토씨까지 같게
- 재질 묘사 — 같은 문장을 반복
- 색 — 같게

**다르게 쓰는 건 딱 하나**, 바꾸려는 조건뿐이다 (예시에서는 태양 각도).
나머지가 한 글자라도 다르면 대비가 아니라 딴 장면이 된다.

## 연쇄 컷

한 씬 안에서 동작을 여러 단계로 이어 붙일 때는 `먼저 … 이어서 … 그 다음 …
마지막으로 …` 로 쓰고, 끝에 **"카메라는 끊김 없이 하나의 연속 동작으로
움직인다"** 를 넣는다. 이게 없으면 Flow가 컷을 나눠버린다.

## 생성 길이 vs 사용 길이

Flow 클립은 끝으로 갈수록 모션이 무너진다. **쓸 길이보다 1초 이상 길게
생성하고 뒤를 버린다.** `scenes.json`에는 사용 길이만 적는다.

## 씬 배치 — 5컷 · 전부 6초 생성

**컷 수와 길이를 정할 때 현재 Flow 화면의 크레딧 표시를 확인한다.** 숫자는
모델·계정·시점에 따라 달라질 수 있다. 5회를 누르기 전에 화면의 현재 차감
숫자에 5를 곱해 필요한 합계를 확인한다. 잔액이 부족하면 결제나 생성을 자동으로
진행하지 않는다.

6초로 생성해 1초 이상 버리므로 **컷 하나가 5초를 넘으면 안 된다.**
그래서 대본은 **컷당 한 문장, 전체 20~23초**로 쓴다.

| 씬 | 역할 | 색조 |
|---|---|---|
| C1 | 훅 · 문제 단언 | 차가운 톤 |
| C2 | **★전환★** 반전 문장 | 차가움 → 따뜻함 |
| C3 | **★핵심★** 메커니즘 A | 따뜻한 톤 |
| C4 | **★핵심★** 메커니즘 B — A와 대비 | 따뜻한 톤 |
| C5 | 대구 엔딩 | 따뜻한 톤 |

C3와 C4를 **같은 구도에서 조건 하나만 바꾸는 쌍둥이 컷**으로 잡는 게 핵심이다.
대비가 메커니즘을 설명한다.

## 대본을 쓸 때

- **한 문장 = 한 컷.** 두 문장을 한 컷에 넣으면 6~7초가 되어 6초 생성으로 못 덮는다
- 문장은 **5초 안에 읽히는 길이**로. 한국어로 대략 25자 안팎
- 전체 **20~23초**를 넘기지 않는다

TTS를 돌려 재봤을 때 어느 컷이든 5초를 넘으면 **그 문장을 줄인다.**
컷을 늘리는 건 크레딧이 허락하지 않는다.

## 재생성 전에 남은 크레딧 확인

계정에 따라 다시 뽑을 여유가 없을 수 있으므로 프롬프트를 보내기 전에 반드시
확인한다.

- 카메라 무빙이 한 문장으로 들어 있는가 (빠지면 정지컷이 나온다)
- 끝에 "한글이나 한국어 문자는 넣지 않는다"가 붙어 있는가

남은 크레딧이 한 번 부족하면 **4컷으로 줄이는 복구안**을 먼저 보여 준다. C3·C4
쌍둥이 컷만 지키면 구조는 산다.

## 늘리려면

크레딧이 넉넉해지면 컷을 늘린다. 새 아이디어가 아니라 **기존 컷을 쪼갠다.**

- C1 → 해결책마다 한 컷씩 (블라인드 / 코팅 / 두꺼운 유리)
- C3·C4 → 연쇄 단계를 별도 컷으로 분리
- C5 앞에 **완전 정지컷**을 넣어 대구 A/B를 만든다 — 앞이 계속 움직였기 때문에
  정지 자체가 리듬이 되고 마지막 무빙이 살아난다

한여름 태양은 머리 위 75도, 처마가 잘라냅니다.
한겨울엔 30도로 내려앉아 방 안까지 듭니다.
사철 같은 집과, 사철 다른 집의 차이입니다.

## scenes.json

타임캐스트 `ssfm-v30` · Sanghyun으로 실제 합성해 측정한 낭독 길이는
**21.0초**다. 컷 경계를 문장 시작점에 맞춘 값:

```json
[
 {
  "file": "clips/c01.mp4",
  "use": 4.4
 },
 {
  "file": "clips/c02.mp4",
  "use": 4.8
 },
 {
  "file": "clips/c03.mp4",
  "use": 4.6
 },
 {
  "file": "clips/c04.mp4",
  "use": 3.8
 },
 {
  "file": "clips/c05.mp4",
  "use": 3.5
 }
]
```

전 컷은 6초로 다섯 번 생성하는 설계다. 가장 긴 사용 컷이 4.8초라 영상 길이에는
여유가 남는다. 실제 필요한 크레딧은 생성 직전 Flow 화면에서 확인한다.

## 씬 길이는 낭독 뒤에 정한다

**대본을 눈으로 읽고 씬 길이를 추정하지 말 것.** 이 예시를 11컷으로 만들던
때 감으로 45초를 잡았는데 실측은 58.7초였다 — 23% 어긋났다.

순서는 이렇다.

1. 대본을 쓴다 (컷당 한 문장, 20~23초)
2. `tts.py`를 먼저 돌린다 → `words.json`
3. 문장 시작 시각을 보고 컷 경계를 정한다
4. **어느 컷이든 5초를 넘으면 그 문장을 줄이고 다시 돌린다**
5. 그 값으로 `scenes.json`을 쓰고 Flow에서 생성한다

```bash
python3 -c "
import json
w=json.load(open('work/words.json')); seen=set()
for x in w:
    if x['sentence'] not in seen:
        seen.add(x['sentence']); print(f\"{x['start']:6.2f}s  {x['text']}\")"
```

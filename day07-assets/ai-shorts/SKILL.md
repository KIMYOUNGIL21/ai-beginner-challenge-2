# AI 쇼츠 제작

주제 하나에서 완성된 9:16 MP4까지.

```
1 주제·대본 ─ 2 TTS ─ 3 씬 프롬프트 ─┤ 4 Flow 클립 생성 ├─ 5 배치 ─ 6 조립
              자동                       현재 수동          자동
```

**TTS를 씬 프롬프트보다 먼저 돌린다.** 씬 길이는 낭독 길이에서 나오지,
대본을 눈으로 읽고 추정할 수 있는 값이 아니다. 예시 대본도 감으로 잡은 길이와
실측 길이가 크게 어긋났다. 순서를 뒤집으면 Flow 크레딧을 쓴 뒤에 길이가 안 맞는
걸 알게 된다.

**현재 손이 가는 건 4번뿐이다.** 그 앞은 전부 생성해 주고, 그 뒤는 전부
스크립트가 처리한다. 경계 양쪽을 매끄럽게 만드는 데 집중한다: **넘겨줄 땐
프롬프트를 붙여넣기 좋게, 받을 땐 파일 이름을 사람이 안 만지게.**

4번은 고정된 제약이 아니다. 다만 **자동화나 유료 대안을 먼저 권하지 않는다.**
사용자가 직접 물어볼 때만 답한다. 어느 방식으로 클립을 얻든 **5·6번은 출처와
무관하게 그대로 동작한다.**

## 0. 평문 요청 처리

설명서는 초보자가 셸 명령 대신 평문으로 부탁하도록 안내한다.
아래 요청이 오면 **사용자에게 명령을 치게 하지 말고 직접 실행한다.**
결과도 평문으로 옮긴다 — `ffmpeg`, `Pillow`, `words.json` 같은 이름을 그대로
던지지 말고 무엇을 위한 것인지 붙인다.

| 사용자가 말하면 | 한다 |
|---|---|
| 쇼츠 만드는 데 필요한 프로그램 확인하고, 없으면 설치해줘 | 먼저 `scripts/setup.sh`로 읽기 전용 점검. 빠지면 시작 패키지의 운영체제별 PRECHECK와 INSTALL_CLINIC 안내. 임의 설치 금지 |
| 타임캐스트를 안전하게 연결하고 싶어 | 키를 채팅으로 받지 않고 `TYPECAST_SETUP.html`의 4단계(파일에 붙여넣기)를 안내 |
| 쓸 수 있는 목소리 보여줘 / 목소리 바꿔줘 | `voices.py`로 샘플을 만들어 들려주고 고르게 |
| 컷별로 프롬프트랑 생성 길이 하나씩 보여줘 | C1부터 하나씩, 복사하기 좋게 |
| `C1` 프롬프트 복사해줘 / 다음 | 그 컷 프롬프트만 클립보드로 (`pbcopy`) |
| 클립 다 받았어. 영상 끝까지 만들어줘 | 배치 → 확인 → 조립 |
| 크레딧 없어. 있는 클립으로 맞춰줘 | 받은 클립만으로 `scenes.json` 재계산 후 조립 |
| 결과 폴더 열어줘 | `open`(mac) / `explorer`(win)로 작업 폴더 열기 |
| 목소리 샘플 폴더 열어줘 | 샘플 폴더를 파일 탐색기로 열기 |
| 다 설치됐는지 다시 확인하고, 안 된 게 있으면 알려줘 | `setup.sh` 읽기 전용 점검 후 결과만 요약 |
| 클립은 `<폴더>` 폴더에 있어 | `ingest.py --from <폴더>` |
| `N`번 컷에 들어갈 파일은 `<파일>` 야 | `ingest.py --map N=<파일>` |
| 길이 안 맞는대. 맞춰줘 | `scenes.json`의 `use` 값을 직접 조정 후 재조립 |
| 이어서 해줘 | 마지막으로 멈춘 단계부터 재개 |

### 준비 확인

빠진 게 있으면 **임의 설치 명령을 실행하거나 사용자에게 붙여넣게 하지 않는다.**
시작 패키지의 `PRECHECK_MAC.md` 또는 `PRECHECK_WINDOWS.md`와
`INSTALL_CLINIC.md`를 보여 주고 운영자 확인을 요청한다. 프로그램이 이미 준비된
경우에만 `install_mac.sh` 또는 `install_windows.ps1`의 대상과 백업 위치를 먼저
설명하고 사용자 승인 뒤 Skill과 전용 환경을 설치한다.

**끝났으면 반드시 "준비 완료"라는 말로 끝낸다.** 설명서가 그 문구를 성공
신호로 안내하고 있다. 하나라도 실패했으면 그 말을 쓰지 않고, 무엇이 안 됐는지
와 다음에 뭘 하면 되는지를 알린다.

### 키 등록

**API 키를 채팅으로 받지 않는다.** 시작 폴더의 `TYPECAST_SETUP.html`를 보여 주고,
사용자가 시작 폴더의 `typecast-key.txt`를 직접 열어 키를 붙여넣고
저장하게 한다. `typecast-key.txt`의 내용은 읽거나 출력하지 않고,
파일 존재만 확인한다. 음성 합성은 시작 폴더의
`run_tts_secure_mac.sh` 또는 `run_tts_secure_windows.ps1`로 실행한다.

### 목소리 — 이름만 보여주지 말고 들려준다

**목록만 나열하는 것은 답이 아니다.** 이름·성별·태그로는 어떤 소리인지 알 수
없고, API 메타데이터에는 **한국어를 잘하는지 알려주는 항목이 아예 없다.**
반드시 소리를 만들어 들려준 뒤 고르게 한다.

Mac은 시작 폴더의 `run_voices_secure_mac.sh`, Windows는
`run_voices_secure_windows.ps1`을 사용한다. 이 실행 파일이 로컬 보안 파일을
현재 프로세스에만 불러온 뒤 `voices.py`를 실행하고, 끝나면 키를 해제한다.

후보들이 **같은 문장**을 읽은 파일이 나온다. 각자 "1번", "2번" 하고
자기 번호를 먼저 말하므로 듣다가 놓치지 않는다.

**폴더의 절대 경로를 반드시 알려준다.** 파일 이름만 말하면 초보자는 못 찾는다.
요청하면 `open`(mac) / `explorer`(win)으로 열어준다.

- `voices/00-전체듣기.wav` — 다섯을 이어붙인 것. 이것부터 들어보라고 한다
- `voices/01-이름.wav …` — 개별 파일

번호·이름·성별·나이·용도를 표로 보여주고 **번호로 고르게** 한다.
고르면 `voices.json`에서 `voice_id`만 꺼내 프로젝트의 `my-short/voice.txt`에
저장한다. `voice_id`는 비밀이 아니다. `typecast-key.txt`와
`~/.config/ai-shorts/secrets.env`는 열거나 수정하지 않는다. 전체 음성 실행 때 `voice.txt`의 ID를 안전 실행기 인자로 넘긴다.

마음에 드는 게 없으면 `--query`를 바꿔 다시 돌린다. 샘플 한 문장은
크레딧을 거의 쓰지 않는다.

### 프롬프트는 클립보드로 넘긴다 — 화면에 뿌리기만 하면 안 된다

프롬프트는 300~400자다. **터미널에서 마우스로 긁으면 줄이 접혀 잘린다.**
끝의 "한글이나 한국어 문자는 넣지 않는다"까지 온전히 가야 하는데 그게 안 된다.
여기서 사용자가 실제로 막힌다.

**그래서 세 가지를 같이 한다.**

1. `prompts.md`를 작업 폴더에 쓴다 — 컷마다 코드블록으로. 편집기에서 열어
   복사할 수 있는 안전한 사본이다.
2. **요청하면 클립보드에 넣어준다.** 사용자가 `C1 프롬프트 복사해줘` 라고
   하면 그 컷의 프롬프트만 클립보드로 보낸다.
   - macOS: `pbcopy`
   - Windows: `clip`
   복사했다고만 말하고 **프롬프트 전문을 다시 화면에 뿌리지 않는다.**
3. 화면에도 보여주되, **읽어서 확인하는 용도**임을 밝힌다.
   "긁어서 복사하지 말고 `C1 프롬프트 복사해줘` 라고 하세요."

**목록은 C1~C5를 한 번에 보여준다.** Flow는 병렬 생성이 되므로 하나씩 주고
기다리게 하면 사용자를 붙잡아 두는 것이다.

클립보드는 **요청받은 컷만** 넣는다 — `C3 프롬프트 복사해줘` 처럼.
순서대로 강제하지 않는다.

### 컷별 프롬프트 제시

**프롬프트만 던지지 않는다.** 어디에 어떻게 넣는지를 항상 같이 말한다.
터미널에서 쓰는 사용자는 설명서를 보고 있지 않다.

**5개를 한 번에 준다.** Flow는 앞 영상이 만들어지는 동안 다음 것을 걸 수
있으므로, 하나씩 주고 "다음"을 기다리면 사용자를 불필요하게 붙잡아 둔다.

먼저 설정을 안내한다 (4번의 표 내용). 특히 **9:16과 x1**, 그리고
**현재 화면의 생성 시 사용 크레딧** 확인을 짚는다.

그다음 C1~C5를 번호를 붙여 각각 코드블록으로 준다. 형식:

> **C1** — 6초 · 9:16 · x1
> ```
> (프롬프트 전문)
> ```

마지막에 진행 요령을 붙인다:

> 다섯 개를 **연달아 거세요.** 앞 영상이 끝날 때까지 기다릴 필요 없습니다 —
> C1 생성을 누르고 바로 C2를 붙여넣어 걸면 됩니다.
> **다운로드는 완성되는 순서대로 하나씩** 받으세요. Shift로 한꺼번에 받으면
> 파일 순서를 알 수 없게 되어 컷이 뒤섞입니다.
> 다 받으시면 `클립 다 받았어. 영상 끝까지 만들어줘` 라고 말씀해 주세요.

### Day 6 주문서 이어받기

시작 폴더에 `day06-handoff/brief.json`이 있으면 새 주제를 제안하기 전에 먼저
사용할지 묻는다. 사용자가 동의하면 시작 패키지의 `import_day6_brief.py`를
운영체제에 맞는 Python으로 실행한다. 이 파일은 다음을 모두 검사한 뒤에만
`my-short/script.txt`를 만든다.

- `schema_version`이 `shorts-brief-v1`
- `scenes`가 C1~C5 정확히 다섯 개
- 각 scene에 `id`, `role`, `narration`, `visual`, `planned_seconds`
- 기획 합계 20~23초, 각 컷 5초 이하

`shorts-brief.html`은 사람이 눈으로 비교하는 읽기 전용 확인본이다. 원본 두
파일은 수정·이동·삭제하지 않는다. 가져온 다섯 문장을 보여주고 사용자가 한
문장을 고칠 기회를 준 뒤 목소리 단계로 간다. Day 6 파일이 없으면 1번부터 한다.

### 전역 설치

시작 패키지의 `install_mac.sh` 또는 `install_windows.ps1`을 사용한다. 대상과 기존
Skill 백업 위치를 먼저 설명하고 승인 뒤 실행한다. 설치 스크립트는 전용 Python
환경과 Pillow만 준비한다. `setup.sh`는 이후 읽기 전용 확인에만 사용한다.

## 1. 주제 고르기 — 하나만 던지지 않는다

사용자가 넓은 분야만 말하면(예: "건축", "과학") **곧바로 대본을 쓰지 말고
후보를 여러 개 만들어 고르게 한다.** 주제가 구조에 안 맞으면 대본부터
뒤집어야 하는데, 그건 Flow 크레딧을 쓰기 전에 걸러야 한다.

후보는 **8개**를 낸다. 각각 이 형식으로, 한 줄씩:

> **3. 아파트 발코니** — "발코니는 왜 사라졌을까요?"
> 확장이 합법화되면서 방으로 먹혔다 → 그런데 원래 발코니는 **화재 대피로**였다

제목 / 훅 한 줄 / **반전이 뭔지** 를 반드시 같이 보여준다. 반전이 안 보이는
후보는 넣지 않는다 — 이 구조에서는 대본이 안 나온다.

### 좋은 주제의 조건

- **"흔히 이렇게 안다 → 사실은 반대다"** 가 성립한다
- 반전이 **눈에 보이는 메커니즘**이다 (추상적 개념이면 C3·C4를 못 만든다)
- 그 메커니즘을 **조건 하나만 바꿔 대비**할 수 있다 (여름/겨울, 전/후, 있음/없음)

세 번째가 특히 중요하다. 쌍둥이 컷이 안 나오는 주제는 영상이 밋밋해진다.

### 분야를 안 정했으면

먼저 묻는다 — 어떤 쪽인지, 그리고 **본인 채널이 이미 있는지**.
있으면 그 채널 결에 맞춘다. 없으면 눈에 보이는 소재가 많은 쪽을 권한다:
건축·토목, 생활 속 물건의 설계, 음식의 물리·화학, 교통·인프라.

역사·인물·추상 개념은 좋은 이야기가 되지만 **보여줄 메커니즘이 없어서**
이 파이프라인과는 잘 안 맞는다. 그런 주제를 고르면 그 점을 미리 알린다.

## 2. 대본

사용자가 후보를 고르면 대본을 쓴다. `references/prompt-formula.md`의
**반전 구조**를 따른다.

1. 현재 방식의 실패를 단언한다 (훅)
2. "우리는 X만 찾았고, Y는 그러지 않았습니다"로 뒤집는다
3. 진짜 메커니즘을 보여준다 — 조건 A
4. 같은 메커니즘 — 조건 B (A와 대비)
5. 대구로 닫는다

**컷당 한 문장, 5문장, 전체 20~23초.** 한 문장이 5초를 넘으면 안 된다.
초안을 보여주고 사용자가 고칠 기회를 준다. `script.txt`로 저장한다.

## 3. 목소리 고르기 — TTS보다 먼저

**전체 낭독을 만들기 전에 목소리부터 정한다.** 목소리가 바뀌면 낭독 길이가
달라지고, 낭독 길이가 컷 길이를 정하므로, 나중에 바꾸면 Flow 클립이 전부
무효가 된다.

대본 첫 문장으로 후보를 뽑아 들려준다 (위 「목소리 — 이름만 보여주지 말고
들려준다」). 사용자가 번호로 고르면 그 `voice_id`로 4번을 진행한다.

프로젝트에 `my-short/voice.txt`가 있고 사용자가 바꾸겠다고 하지 않으면 이 단계를
건너뛸 수 있다. 다만 **처음 쓰는 사용자에게는 한 번 들려준다.**

## 4. 내레이션 — Typecast Timestamp TTS

```bash
# Mac — 시작 폴더에서
./run_tts_secure_mac.sh my-short/script.txt my-short/work tc_xxxxxxxx

# Windows PowerShell — 시작 폴더에서
.\run_tts_secure_windows.ps1 -ScriptFile my-short/script.txt -WorkDir my-short/work -VoiceId tc_xxxxxxxx
```

`tc_xxxxxxxx`에는 `my-short/voice.txt`의 값을 넘긴다. 이 파일은 읽어도 되지만
`typecast-key.txt`와 `~/.config/ai-shorts/secrets.env`는 열거나 수정하지 않는다.

`work/narration.wav` + `work/words.json`(단어별 start/end)이 나온다.

그다음 **바로 `plan.py`를 돌려 컷 길이를 확정한다.** 눈으로 계산하지 않는다.

```bash
<스킬>/.venv/bin/python <스킬>/scripts/plan.py my-short/work --out my-short/scenes.json
```

타임스탬프는 **합성 과정에서 나온 값**이므로 STT/Whisper 정렬은 쓰지 않는다.
목소리를 직접 녹음한 경우에만 별도 정렬이 필요하다.

보이스 고르기: 원하는 톤을 문장으로 설명해
`GET /v1/voices/recommendations?query=...`로 후보를 받는다. 응답은
`voice_id`/`voice_name`/`score`만 주므로, 고르기 전에 `GET /v2/voices/{id}`로
모델·감정 지원 여부를 확인한다. 전체 탐색은 `GET /v2/voices`.

`words.json`의 문장 시작 시각이 다음 단계의 컷 경계가 된다.

```bash
python3 -c "
import json
w=json.load(open('work/words.json')); seen=set()
for x in w:
    if x['sentence'] not in seen:
        seen.add(x['sentence']); print(f\"{x['start']:6.2f}s  {x['text']}\")"
```

## 5. 씬 프롬프트 — 넘겨주는 쪽

`references/prompt-formula.md`의 **일곱 칸 문법**을 그대로 적용한다.
특히 **② 재질과 ③ 광원을 빼먹지 않는다** — 이 둘이 빠지면 결과가 렌더처럼
밋밋해진다. "시네마틱", "고퀄리티" 같은 말은 쓰지 않는다.

C3·C4 쌍둥이 컷은 **바꾸려는 조건 하나를 빼고 문장을 그대로 복사**한다.
Flow는 앞 컷을 기억하지 못하므로 "앞과 동일하게"로는 안 맞는다.

**기본은 5컷, 전부 6초 생성이다.** 생성 직전 **현재 Flow 화면의 차감 숫자를
읽고 5회 합계를 계산**한다. 숫자는 모델·계정·시점에 따라 달라질 수 있으므로
현재 화면을 기준으로 하고, 잔액이 부족하면 결제나 생성을 진행하지 않은 채
사용자에게 알린다.

6초로 뽑아 1초 이상 버리므로 **컷 하나가 5초를 넘으면 안 된다.** 따라서
대본은 **컷당 한 문장, 전체 20~23초**로 쓴다. 2번에서 재봤을 때 5초를 넘는
컷이 있으면 **컷을 늘리지 말고 그 문장을 줄여 다시 돌린다.**

재생성 여유가 0이므로 프롬프트를 보내기 전에 카메라 무빙이 들어 있는지
확인하게 한다. 실패가 걱정된다면 4컷으로 줄여 1회를 예비로 남길 수 있다.

늘려 달라고 하면 새 아이디어를 넣지 말고 **기존 컷을 쪼갠다**
(`prompt-formula.md`의 "늘리려면").

두 개를 만든다.

**`prompts.md`** — 사람이 Flow에 붙여넣을 것. 씬마다 이 형식으로:

````
### C3 · 6초 생성 → 4.6초 사용 · 연쇄 3단
```
(프롬프트 전문 — 코드블록에 넣어 복사가 한 번에 되게)
```
````

씬 번호와 **생성 길이**를 제목에 적는다. Flow에서 길이를 그걸로 맞춘다.

**`scenes.json`** — **손으로 계산하지 않는다.** `plan.py`가 `words.json`에서
문장 시작 시각을 읽어 만든다:

```bash
<스킬>/.venv/bin/python <스킬>/scripts/plan.py my-short/work --out my-short/scenes.json
```

컷이 5초를 넘으면 어느 문장인지 알려주고 **중단한다.** 그 문장을 줄이고
`tts.py`부터 다시 돈다 — 컷을 늘리는 건 크레딧이 허락하지 않는다.
나오는 모양은 이렇다:

```json
[{"file": "clips/c01.mp4", "use": 4.2},
 {"file": "clips/c05.mp4", "use": 3.4}]
```

합계가 내레이션 길이와 맞는지 확인한다. 안 맞으면 Flow에서 다시 뽑아야 한다.

그리고 사용자에게 안내한다: [Flow](https://labs.google/fx/ko/tools/flow)에서
**C1부터 순서대로** 생성하고 받은 파일은 이름 그대로 두라고. 순서만 지키면
다음 단계가 알아서 맞춘다.

## 6. Flow 클립 생성 — 사람 단계

여기서 멈추고 기다린다. 사용자가 다 받았다고 하면 7번으로 간다.

**설정을 잘못 잡으면 크레딧이 순식간에 날아간다.** 프롬프트를 주기 전에
반드시 아래를 먼저 안내한다.

### Flow 설정 — 프롬프트보다 먼저

새 프로젝트를 열고 **왼쪽에서 「모든 미디어」**를 고른다. 화면 아래 입력창
오른쪽의 회색 알약(`동영상 · 720p · 6s · x1`)을 누르면 설정 패널이 열린다.

| 항목 | 골라야 할 것 | 틀리면 |
|---|---|---|
| 이미지 / **동영상** | **동영상** | 정지 이미지가 나온다 |
| 프레임 / **애셋** | **애셋** | — |
| **9:16** / 16:9 | **9:16 (세로)** | **기본이 16:9다.** 가로 영상이 나와 쇼츠가 안 된다 |
| 모델 | **Omni Flash** | — |
| 길이 | **6s** | 오늘 대본은 컷당 최대 5초라 6초 생성으로 충분하다 |
| 개수 | **x1** | 한 컷씩 받아 순서와 사용량을 관리한다 |

패널 맨 아래의 **현재 생성 시 사용 크레딧**을 읽고 5회 합계를 계산한다.
숫자는 모델·계정·시점에 따라 바뀔 수 있다. 잔액보다 많이 필요하거나 사용량이
이해되지 않으면 생성하지 말고 모델·길이·개수와 계정의 현재 표시를 사용자에게
확인받는다.

가장 많이 틀리는 둘: **9:16을 안 바꿔서 가로로 뽑는 것**, 그리고
**개수가 x1이 아닌 것**.

### 생성은 연달아, 다운로드는 하나씩

**앞 영상을 기다리지 않는다.** C1 생성을 누른 뒤 바로 C2를 걸 수 있다.
다섯 개를 연달아 걸어두면 전체 대기가 한 번으로 끝난다.

**다운로드는 반드시 하나씩, 완성되는 순서대로 시킨다.**
Shift로 골라 한꺼번에 받으면 파일 저장 시각이 전부 같아져 순서 정보가
사라진다. Flow 파일명은 임의 문자열이라 이름으로도 복원할 수 없고,
결과적으로 컷이 통째로 뒤섞인다.

이미 한꺼번에 받아 버렸다면 `ingest.py`가 감지해 **순서 확인 시트**를
만들어 준다. 그 이미지를 사용자에게 보여주고 순서를 확인받은 뒤
`--map N=파일` 로 지정한다. 추측해서 `--apply` 하지 않는다.

파일 이름은 바꾸지 않는다.

### 프롬프트 전달

위 설정을 확인시킨 뒤 C1~C5를 한 번에 준다.

## 7. 배치 — 받는 쪽

```bash
cd my-short
<스킬>/.venv/bin/python <스킬>/scripts/ingest.py scenes.json          # 미리보기
<스킬>/.venv/bin/python <스킬>/scripts/ingest.py scenes.json --apply
```

`~/Downloads`의 최근 영상 파일을 받은 순서대로 빈 씬에 채운다. 옮기기 전에
씬별 길이와 필요 길이를 표로 보여주고, 짧은 클립은 배치하지 않는다.

- 쓸 만한 것만 배치하고 나머지는 "다시 생성 필요"로 알린다
- 배치한 파일과 거부한 파일을 `.ingest.json`에 기록하므로, Flow에서 다시 받아
  같은 명령을 실행하면 순서가 밀리지 않고 재생성분이 제자리에 들어간다
- 순서가 꼬였으면 `--map 7=~/Downloads/foo.mp4`로 개별 지정
- 원본은 복사만 하고 지우지 않는다

```bash
<스킬>/.venv/bin/python <스킬>/scripts/check.py scenes.json
```

무엇이 남았는지 한 번에 보여준다. `5/5 준비됨`이 나오면 다음으로 간다.

## 8. 조립

### 크레딧이 떨어져 클립이 모자랄 때

현재 계정의 남은 크레딧이 부족해 **한 컷을 다시 뽑을 수 없다면**
사용자가 `크레딧 없어. 있는 클립으로 맞춰줘` 라고 하면:

1. 받은 클립만으로 `scenes.json`을 다시 쓴다 — 빠진 컷의 시간을
   **앞뒤 컷에 나눠 붙인다** (문장 경계는 유지)
2. 자막은 `words.json` 그대로라 어긋나지 않는다
3. 영상은 짧아지지만 완성된다

**"다시 뽑으세요"로 끝내지 않는다.** 크레딧이 없는 사람에게는 답이 아니다.

```bash
<스킬>/.venv/bin/python <스킬>/scripts/build.py scenes.json work/ --out D07_닉네임_쇼츠.mp4
```

각 클립을 사용 길이로 자르고 → 1080x1920으로 크롭 → 이어붙이고 →
내레이션을 깔고 → `words.json` 타이밍으로 자막을 태워 넣는다.

영상 길이와 내레이션 길이가 1초 넘게 어긋나면 경고가 뜬다. 그때
`scenes.json`의 `use` 값을 조정한다.

## 한 번에 돌리기

4~6번을 순서대로 실행하는 기술용 래퍼가 있다. 다만 이 교육 패키지에서는 키를
환경에 직접 노출하지 않기 위해 **전체 음성은 먼저 안전 실행기로 만들고**, 이후
배치·확인·조립 스크립트를 개별 실행하는 흐름을 기본으로 한다.

```bash
<스킬>/scripts/make-short.sh my-short D07_닉네임_쇼츠.mp4
```

폴더에 `script.txt`와 `scenes.json`만 있으면 된다. 중간에 멈추면 무엇이
부족한지 알려주고, 고친 뒤 같은 명령을 다시 실행하면 이어서 간다.
이미 만든 내레이션은 재사용한다 — TTS는 크레딧이 나가므로 다시 만들려면
`FORCE_TTS=1`. 다운로드 폴더가 `~/Downloads`가 아니면 `DOWNLOADS=경로`.

`scripts/setup.sh`는 읽기 전용 상태 확인이다. 빠진 프로그램이 보이면 시작
패키지의 PRECHECK와 INSTALL_CLINIC로 돌아간다.

## 전제 조건

- `ffmpeg` / `ffprobe`
- 자막용: libass 빌드 ffmpeg **또는** Pillow. Homebrew ffmpeg 9는 libass가 없어
  Pillow 경로로 떨어진다 — `python3 -m venv .venv && .venv/bin/pip install pillow`
  후 `build.py`를 `.venv/bin/python`으로 실행한다.
- `TYPECAST_API_KEY` (웹 플랜과 별도인 **API 플랜** 필요)

## 주의

- 타임캐스트의 API 요금제·크레딧·이용 조건은 바뀔 수 있다. 실제 호출 전에
  개발자 페이지에 표시된 현재 플랜과 예상 사용량을 사용자에게 확인시키고,
  결제나 업그레이드를 자동으로 진행하지 않는다. 수익 창출 채널의 라이선스도
  현재 약관을 사용자에게 확인시킨다.
- 씬 프롬프트 끝에 "한글이나 한국어 문자는 넣지 않는다"를 항상 붙인다.
  Flow가 화면에 글자를 그려 넣으면 자막과 충돌한다.
